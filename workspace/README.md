# Workspace

One folder per project. Same files on phone and PC. Nothing is real until it's pushed.

## Just talk to it

| Say this | What happens |
|---|---|
| "add a thought to smile flow: ..." | Filed into that project's `log.md`, committed, pushed |
| "where did I leave off on smile flow?" | A short brief: status, last 3 things, next action |
| "wrap up" | This session gets summarized into the log, then pushed |
| "new project <name>" | A project folder is scaffolded |
| "save this prompt version" | Recorded in `prompts/`, old version kept and retired |
| "log a result: ..." | A dated result entry with numbers you can compare later |

Slash commands do the same thing if you'd rather type: `/drop` `/catchup` `/wrap`
`/newproject` `/prompt` `/result` `/import-history`.

## How it's organized

```
projects/<slug>/
  README.md    where it stands right now — Status and Next at the top
  log.md       everything that happened, newest entry on top
  prompts/     one file per prompt, every version kept
inbox.md       thoughts that don't have a project yet
```

That's the whole system. Three files per project.

## Rules

- **Push after every capture.** A phone session runs in a container that gets deleted
  without warning. Unpushed work is lost work.
- **`log.md` is the truth.** `README.md` is just the current summary of it.
- **Never delete an old prompt version** — mark it retired. The trail is the point.
- Don't know which project something belongs to? It goes in `inbox.md` and gets filed later.
- Entries are tagged `#thought` `#session` `#result` `#decision` `#imported`, and marked
  `[phone]` or `[pc]` so you can see where the thinking happened.
